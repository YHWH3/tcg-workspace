## Complete-run integration corrections

The complete run at `e2934d6` passed 1,209 unit and 590 dedicated D1 assertions, but failed MCP integration gates and one WebKit offline assertion. That report remains a failed historical run; it is not final acceptance evidence.

- **P6-DEV-09:** small record tools ran their handlers twice (plan, then commit), repeating D1 reads and mutating prospective data. Planning's internal service environment must remain ungated so retained tombstone candidates can be passed to canonical write authorization; it never returns their content directly.
- **P6-DEV-10:** the kernel's ordinary comment edit rules rejected parent cascades (foreign comment ownership and `deletedVia`). `comment-cascade-red.log` reproduces this. Only a matching same-plan parent transition can authorize comment tombstone bookkeeping; another author's body stays protected. Restore gathers retained candidates internally and the canonical planner checks the complete inverse before committing. The regression includes a forged standalone cascade refusal.
- **P6-DEV-11:** the new AI-table user foreign keys prevented account removal (`user-removal-red.log`). Only this phase's unpublished migrations 0028/0029 were corrected: user IDs remain retained audit identities without delete-restricting references. Connection lookup joins a current, enabled principal. Account removal neither erases AI audit history nor leaves a usable connection. No previously released migration was changed.
- **P6-DEV-12:** AI screens subscribed to sync's online state before the engine installed its event listeners, so an early WebKit offline transition could be missed. They now subscribe for their own mounted lifetime. The real WebKit nine-journey rerun passed, including offline concealment.

**P6-DEV-13 — stale scheduler test bound.** The next complete run at `7a360cd` exposed a wall-clock-dependent Cron fairness failure. No dirty-source result from this correction is final acceptance evidence.
