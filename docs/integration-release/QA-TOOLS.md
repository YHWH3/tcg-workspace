# Testing tools follow-up, 2026-10-23

The user's screenshots disproved the earlier impression of complete visual/device coverage. Existing passing workflow assertions and engine/viewport sampling did not establish that every feature, open control or native browser window had been visually checked. The UI follow-up remains a separate, source-bound acceptance record.

No tool can infer that an initial reference image is good merely because later images match it; emulation also does not prove physical-device behavior.

One exploratory random action tried to focus the inert shell behind a compact modal. That was a test-model error, not counted as a product defect: exploration now invokes the supported keyboard search shortcut from the detail surface. Each generated case resets its environment for reliable shrinking/replay.

An intermittent local Chromium HTTPS stylesheet request failed with `ERR_TOO_MANY_RETRIES`. Those runs are failures, not passes. The isolated Chromium test process uses a launch-scoped certificate exception alongside its local context; all external requests stay blocked. A render sentinel prevents misleading accessibility results against a page with no stylesheet. This is not production TLS evidence.

## Evidence and durable continuation

Implementation: `scripts/qa-ux.mjs`, `scripts/ux-lab/`, and [the run guide](../testing/UX-LAB.md). The full planned matrix is 31 named cases × 18 projects = 558 cases. A case may contain multiple assertions/scans; the case count is not a count of devices or unique bugs.

The machine-readable run summary records executed/failed/missing cells, source fingerprint, exact browser builds, generated actions and replay information. The coverage page marks unexecuted states NOT RUN. Reference-capture runs remain distinct from ordinary comparison runs and from genuine human review. Final run results are recorded in ignored artifacts after the committed source is frozen; this document does not predeclare their outcome.

Earlier source `5293660` passed the affected v4/v7/v8/v9/Phase5-sync/Phase5-workflows/Phase6-workflows/assistant suites (33/114/140/75/33/36/42/27 cases respectively), and v6/Website/release-UI follow-up (150/9/18). Those exact-source results remain historical evidence; the added UI fixes and development dependencies require current-source validation.

The first complete 522-case discovery run at `2f78028` passed 481 and failed 41. These were repeated instances of a few causes, not 41 unique defects: remaining dark-theme contrast, task draft persistence and harness timing/cancellation classification. Failures are retained under `.artifacts/ux-lab/final-matrix/`. The later 540-case run is described below; the final plan has 558 cases including the unavailable-task state. The discovery run is not acceptance.

WebKit 1.63 promotes some handled Fetch console diagnostics to `pageerror`. The harness retains every diagnostic and accepts only exact local requests correlated with injected offline windows or known read-only requests already in flight when the old document navigated (captured before navigation, with a bounded diagnostic window). Independent window error/unhandled-rejection listeners still fail, including during fault injection. Some handled Fetch refusals never enter the network event stream. Remaining diagnostics are accepted only for the narrowly named read-only endpoints (GET reads and protocol-3 POST pull) after a successful authenticated recovery request from the browser itself; pull recovery uses the current manifest and the protocol minimum of eight rows in a bounded authorized request. URL count is bounded and recovery evidence is attached. No accessibility rules are excluded. View-control tests use unique view records and verify cleanup on the server, preventing shared-fixture timing from contaminating another project.

The first full remediation run at `5721edf` recorded 538 PASS / 2 FAIL / 0 skipped. Trace inspection showed a focused-source test deadline racing the ordinary fallback poll, and a handled WebKit protocol-3 pull diagnostic. The focused-source regression now verifies the server change and triggers the ordinary foreground refresh without blurring input; it does not redefine the polling interval. Handled pull diagnostics require successful bounded protocol-3 recovery in the browser. The failures remain preserved. A separate bootstrap fix renews generated test certificates before expiry, restarts the owned Node process for fresh CA trust, and never overwrites supplied certificate files. Three real-OpenSSL harness regressions cover this behavior. These harness changes do not alter product or native-harness files. The separate UI15 correction changes TaskDetail; affected native record-detail checks must be repeated.

The `507dae2` complete run recorded 555 PASS / 3 FAIL / 0 skipped. Two title-entry cases were investigated using captured input/focus events: no title input reached the field while an earlier foreground reconciliation was finishing. A native key probe reproduced interrupted focus. Text-entry assertions now settle pending requests, click the control and verify focus and each value immediately; 24 repeated instrumented cases passed in the affected two profiles before source freeze. The remaining failure was an invalid test pull limit of one; the protocol minimum is eight. These harness corrections do not claim an additional product fix or turn the failed complete run into a pass.

QA01: The full `bd1b5c8` matrix passed 558/558, but configuration review then reproduced an omitted WCAG 2.1 A rule: a button with visible “Save changes” and unrelated accessible name passed the old tags and failed under complete A/AA tags. The three UI gates now share all A/AA tags through WCAG 2.2, and a controlled regression verifies detection and clean restoration. This is a confirmed coverage defect; it does not infer an application defect from the controlled button. Expanded current-source runs are required.

UI16: The expanded rule found database toolbar naming mismatches: visible “Filter” versus “Filters”, abbreviated “Props” versus “Properties”, and active counts missing from the accessible names for Filter/Sort. Visible and accessible Filter/Sort labels now share the same complete string, including active counts; the property label is written as “Properties” for both. The opened-controls regression checks the active names. The 62-case discovery retained 49 PASS / 13 FAIL: repeated toolbar findings plus the compact negative fixture placed behind an inert modal. The negative fixture now sits in the active dialog. New screenshot references must explicitly record the intended “Props” to “Properties” change; they are not human design approval.
