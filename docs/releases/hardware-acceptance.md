# Hardware and human acceptance packet

This is the remaining physical-device procedure for the PR #12 → #13 release stack. Automated desktop engines, native Simulator Safari, Android Emulator browsers and author-side review do not certify these cases. Start every row **NOT RUN**. A tester must record actual execution before selecting PASS or FAIL; use BLOCKED for inaccessible resources and NOT APPLICABLE only with a concrete capability reason.

Generate one evidence file per session, without overwriting an earlier session:

```bash
node scripts/hardware-acceptance.mjs .artifacts/hardware-acceptance/<date-and-tester>
```

Record the exact source SHA/tree, physical model, OS/build, browser version, assistive technology/version, test origin and time. Store screenshots/video and non-sensitive server counts beside `evidence.json`. Never put credentials, OAuth codes/tokens, cookie headers, personal content or browser profiles in evidence or Git. Leave unavailable cases open.

## Fixture prerequisites

Use an owner-authorized disposable HTTPS environment running the exact candidate with synthetic accounts/content and a valid certificate trusted by the actual device. Do not dismiss certificate warnings, reuse production connectors or test destructive operations on real records. A device must reach the fixture directly; Mac loopback URLs do not refer to the Mac from a phone. Use isolated accounts A and B, a writable test space, a second space A cannot read, a page/block, task/database, moodboard note, upload target and simulated assistant. Turn off real inference. Permission-isolation cases need an explicitly permission-enabled disposable fixture; platform parity with permissions disabled is a separate result.

The optional anonymous test-ingress implementation in `scripts/certification/public-fixture.mjs` guards APIs using an unlogged random cookie and expires after one hour. It is not a production deployment. Its Quick Tunnel does not support SSE and its guard denies WebSocket upgrades; do not use it to certify streaming AI/MCP, live presence or third-party hosts. A complete isolated HTTPS test environment is required for those paths. Keep the fixture owner alive until testing ends, then stop it. Do not copy disposable entry secrets into public reports.

## Stop conditions and release impact

Stop and preserve evidence for any unauthorized disclosure/write, lost sole copy of pending work, duplicate approved operation, persistent sign-in failure or inaccessible essential control. Those are engineering failures requiring reproduction. Unavailable hardware, a human tester or a test host are external acceptance blockers, not observed application defects. Source integration and production deployment remain separate owner-authorized operations; this packet authorizes neither.
