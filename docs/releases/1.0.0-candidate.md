## Migration, backup and failure recovery

All remote commands below are **planned operations requiring separate authorization**, not commands executed by this document or local certification. Use the installed, lockfile-pinned Wrangler (`node_modules/.bin/wrangler`). Check exact account/target and read back remote state before any modifying operation. Production's actual schema is unknown; do not infer it from a Worker deployment date.

1. Assign an operator, maintenance window, acceptable RPO/RTO and incident contact. Quiesce browser/MCP writers, offline reconnects, scheduled work and pending continuations through an approved ingress/maintenance procedure. No maintenance-mode switch is claimed to exist in the application.
2. Inventory the actual migration ledger/schema, records and file-byte counts, ancestry/link integrity, owners/Core memberships, sessions/grants, shares, pending form/event/automation/AI execution and storage headroom. Preserve only non-sensitive counts in release logs.
3. Save the current Worker version/configuration and D1 recovery point. Verify D1 storage backend/plan and actual usable Time Travel window. Reconcile KV grants and DO/session state in the recovery plan; D1 alone is not the complete application state.
4. Prove the production-compatible backup/restore method on an approved isolated target before upgrade. A closed local Miniflare state copy proves local restoration only. It does not prove remote D1, KV or DO recovery.
5. Apply **only pending** migrations 0001–0031 in order. Never edit shipped migrations, skip historical Protocol 2 migrations or rerun raw ALTER statements. Stop at a failed migration and inspect the committed ledger boundary before retrying.
6. Validate data retention, FK integrity, owner/Core access, share pinning, retired snapshot tables, bounded search backlog and all connector/preview/checkpoint tables. Keep permissions disabled unless separately authorized. Deploy the matching Worker/assets only after migration and configuration gates pass.

Planned read-only preflight (remote; approved access required):

```bash
node_modules/.bin/wrangler d1 info workspace-db --config wrangler.jsonc
node_modules/.bin/wrangler d1 migrations list workspace-db --remote --config wrangler.jsonc
node_modules/.bin/wrangler d1 time-travel info workspace-db --config wrangler.jsonc --json
```

Planned schema change, only after backup/data-loss and migration approval:

```bash
node_modules/.bin/wrangler d1 migrations apply workspace-db --remote --config wrangler.jsonc
```

Time Travel overwrites the database and cancels in-flight work. Cloudflare documents seven days of recovery on Free and thirty on Paid; verify the actual plan and bookmark. It does not currently provide a production clone for rehearsal. See [Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/).

**FTS5 backup constraint:** migration 0022 introduces virtual tables. Cloudflare documents D1 export limitations for databases containing virtual tables. Do not promise an ordinary complete SQL export or drop live FTS tables to make backup work. Validate selective authoritative-table exports plus a tested derived-index rebuild where applicable, alongside Time Travel. Preserve schema, triggers, file chunks and execution journals; never treat a few row dumps as a proven complete backup. See [D1 import/export limits](https://developers.cloudflare.com/d1/best-practices/import-export-data/).

The pinned CLI supports explicit table export syntax, but its completeness must be proven on an isolated recovery target before adoption:

```bash
# Example syntax only, not a complete backup and not executed remotely.
node_modules/.bin/wrangler d1 export workspace-db --remote --config wrangler.jsonc --table records --output /secure/operator-backup/records.sql
```

The legacy-mainline fixture (0001–0011) was upgraded to all 31 migrations, retaining original values in 29 existing tables and attachment bytes. Unknown production data still needs preflight. Migration 0011 can irreversibly reclaim tombstoned bytes if it is pending. Migration 0018 drops retired derived snapshots; do not discard unsent client work. Migration 0026 keeps the conservative guest-directory restriction. Migration 0031 separates digest outcomes from historical terminal-processing flags. None authorizes new retention purges.

If a schema/code failure requires recovery, keep traffic/jobs quiesced, capture the current recovery point, obtain explicit approval for writes lost after the chosen bookmark, then use the reviewed exact bookmark:

```bash
# DESTRUCTIVE planned recovery; separate explicit approval required.
node_modules/.bin/wrangler d1 time-travel restore workspace-db --config wrangler.jsonc --bookmark APPROVED_BOOKMARK
```

Record the undo bookmark returned by the restore. Reconcile credentials/revocations, idempotency, changesets, preview checkpoints, dirty queues and DO sessions before serving traffic. Do not resurrect old sessions/grants from a backup without enforcing subsequent revocations or fresh authentication.

Worker rollback does not restore D1/KV/DO data. Use a compatible version only after checking its schema/protocol/authority assumptions; a prior pre-permission build is not an automatically safe fallback. DO migration history can also constrain rollback. Future approved syntax is `node_modules/.bin/wrangler rollback APPROVED_VERSION_ID --name workspace --config wrangler.jsonc`; do not run it speculatively. See [Worker rollback constraints](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/).

Keep `access_state.enabled` unchanged during source integration. Migration defaults off; no local preflight reads or changes production state. Before any later activation, verify current owner/Core membership, record ancestry, private-space policy, guest invitations, People restrictions and pinned shares. Test fresh and old client sessions, incompatible protocol rejection, cross-tab restart, pending outbox quarantine, revoked/regranted access and current connector scope.

Do not clear IndexedDB to conceal reconciliation problems. Do not discard offline work or copy old broad grants into new scope decisions. After private-space/guest data is present, **turning enforcement off is an unsafe rollback** because it can reopen legacy broad reads. Keep enforcement and roll forward compatibly, or recover an explicitly approved consistent security state while traffic is stopped. No activation SQL is supplied as a casual operator shortcut.

## Scheduler, backlog and observability

The committed Cron contract is every fifteen minutes in UTC. The bounded scheduler rotates nine phases: event recovery, reminders, automation recovery, form recovery, date-offset automation, established retention/cleanup, weekly digests, optional embeddings and search indexing. Under sustained budget use, a phase's first position rotates over nine slots (135 minutes); do not promise every phase completes every fifteen minutes. D1's per-invocation binding budget is 45; SQL statements and rows read/written are separate measured resources.

The search pipeline rebuilds bounded dirty chunks and exposes pending status. Monitor dirty backlog size/oldest age and progress before broad traffic; preserve FTS fallback and current access checks. Optional model backlogs must not cause paid calls while features are off. Do not introduce a second scheduler or manually advance execution checkpoints.

| Operational signal | Inspection/action |
|---|---|
| Worker errors | Existing structured error logs and request failures; correlate non-sensitive request/version/time; never log passwords, bearer tokens, approval handles, private form payloads or full stored content |
| API reachability | `/` serves built app; unauthenticated `/api/me` returns 401; OAuth metadata returns current HTTPS resource; authenticated `/api/me` and intended local fixtures verify access. There is no dedicated health endpoint to invent |
| Privacy/cache | `/api/*` no-store; verify headers, public-token redaction and account switch; never put session tokens into URLs |
| Authentication abuse | Existing D1 rate buckets: ten failures/account+IP and forty/client per fifteen minutes, distributed-account cap 300/hour; MCP per-user write cap retained. Do not stress production with password guessing |
| Resource headroom | Owner/admin `GET /api/admin/usage` provides explicit aggregates, history/search/file summaries and query metadata; refresh intentionally, not a tight polling loop |
| Recovery backlog | Track unprocessed/terminal outbox, pending AI previews/checkpoints, retry/dead-letter state, digest `outcome`, search dirty age and oldest pending work. A terminal processing flag alone is not proof of notification delivery |
| Incident alerting | Assign a person and contact path, log access and retention; establish free existing Cloudflare failure/usage alerts appropriate to the account; no third-party paid system required |

Release must record operator-selected capacity thresholds and escalation times from actual account limits and measured workload. Local Miniflare latency does not establish production latency or free-plan capacity. Do not claim alert routing is configured merely because observability is enabled.

After future release authorization, an operator can inspect a bounded log-tail session with `node_modules/.bin/wrangler tail workspace --config wrangler.jsonc --format json`, keeping raw sensitive diagnostics out of Git. A live tail is not a replacement for retained incident evidence. Diagnose safely, stop writers for integrity incidents, capture version/recovery points, then choose a permission-compatible roll-forward/rollback under explicit approval.

## Repeatable local release checks

The candidate extends the existing certification pipeline rather than introducing a second framework:

```bash
npm run build
npm run release:preflight
npm run release:rehearse
npm run release:ui -- --skip-build
```

`release:preflight` checks the local source and built deployment contract without network or credential access. `release:rehearse` creates fresh local Miniflare databases, verifies the accepted eleven-migration mainline upgrade through migration 0031, injects a transactional migration failure, restores an owned pre-upgrade copy and validates final logical state, file bytes and FTS reconstruction. It does not use or restore production data. `release:ui` exercises six widths on Chromium, Firefox and WebKit with applicable automated accessibility rules, keyboard/touch and reduced-motion checks. Each command records explicit fail-closed results.

All three are mandatory in complete `npm run certify:phase6`, alongside every earlier gate. Run that command on clean committed source for final acceptance; standalone development checks do not replace it. Real device, human accessibility, real MCP-host and production recovery gates remain separate.
